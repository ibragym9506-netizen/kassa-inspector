# Kassa Inspector — видеоконтроль кассовой дисциплины

Решение команды для **Datathon 26, кейс ForteBank**: локальный AI-сервис, который анализирует видеозапись работы кассира, находит визуально наблюдаемые признаки нарушений кассовой дисциплины и для каждого показывает тип, таймкод, описание, кадр-доказательство и норматив Республики Казахстан.

> Результат работы сервиса — подсказка для проверяющего, а не юридическое или дисциплинарное заключение.

**Команда:** Абу — ML · Али — аналитика и нормативная база · Ибрагим — инженерия · Велемир — питч.

## 2. Запуск

Сервис работает **полностью локально**. Интернет нужен только один раз — чтобы скачать зависимости и веса модели. После этого обработка видео идёт без сети (требование переносимости в контур банка).

### Требования
- Python 3.10+ (на macOS работает и 3.9)
- Для ML: NVIDIA GPU (проверено на RTX 3050 4 ГБ) или CPU (медленнее)

### Установка (Windows, cmd, в папке `forte-service`)
```bat
python -m venv venv
venv\Scripts\pip install fastapi uvicorn[standard] python-multipart opencv-python-headless
venv\Scripts\pip install -r requirements-ml.txt
venv\Scripts\hf download Qwen/Qwen3-VL-2B-Instruct
```
`torch` нужно ставить сборкой под свою CUDA: https://pytorch.org/get-started/locally/

### Запуск
```bat
set API_KEY=<секретный-ключ>
venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```
Интерфейс: `http://localhost:8000`. Публичный адрес — через Cloudflare Tunnel:
```bat
cloudflared tunnel --url http://localhost:8000 --protocol http2
```

### Настройки (переменные окружения)
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `API_KEY` | — | ключ для заголовка `X-API-Key` (обязательно) |
| `ML_ENGINE` | `auto` | `vlm` — Qwen через transformers; `ollama` — запасной движок; `off` — без ML |
| `VLM_MODEL` | `Qwen/Qwen3-VL-2B-Instruct` | модель (только с лицензией, разрешающей коммерческое использование) |
| `VLM_BUDGET_SEC` | `240` | бюджет времени на одно видео |
| `VLM_MIN_CONF` | `0.6` | порог уверенности модели |
| `FAKE_EVENTS` | — | `1` — тестовое нарушение для проверки интерфейса |

### Проверка качества
```bat
venv\Scripts\python -m app.evaluate путь\к\датасету
```
Сравнивает ответы сервиса с разметкой `open_labels.xlsx`: точность вердикта, попадание таймкода, время на ролик.

## 3. Архитектура и подход

```
 .mov ──► POST /analyze ──► очередь задач ──► pipeline.analyze_video (≤ 240 с)
                                                 │
            ┌────────────────────────────────────┤
            ▼                                    ▼
   1. Проход движения (OpenCV)        2. Визуальная языковая модель
      оценка активности каждого          Qwen3-VL-2B смотрит на окна по 3 кадра
      3-секундного окна; выбор           и отвечает строгим JSON: какое из
      самых активных окон + равно-       известных нарушений видно (или нет)
      мерное покрытие ролика             и с какой уверенностью
            └────────────────┬───────────────────┘
                             ▼
                 3. Правила и справочник (rules.py)
                    ключ нарушения → русское название, описание,
                    норматив РК; неизвестные ключи и низкая
                    уверенность отбрасываются
                             ▼
                 4. Кадры-доказательства (OpenCV → JPEG base64)
                             ▼
              GET /jobs/{id} ──► веб-интерфейс / JSON для жюри
```

**Почему так:**
- **VLM вместо обучения детектора.** 48 обучающих роликов мало для обучения своей модели, а финальный тест снят под другим ракурсом и может содержать новые типы нарушений. Визуальная языковая модель отвечает на вопросы о смысле сцены («дверь открыта?», «деньги на столе, кассира нет?»), не привязана к координатам в кадре и переносится на новый ракурс.
- **Окна по движению.** Нарушения происходят в моменты действий, поэтому модель в первую очередь смотрит на самые активные отрезки — так ролик до 145 с укладывается в лимит 5 минут на скромной видеокарте.
- **Тексты и нормативы — из справочника, а не от модели.** Модель возвращает только ключ нарушения. Название, описание и ссылка на норматив берутся из проверенного справочника — это исключает выдуманные пункты.
- **Явный список «не нарушений».** Модели передаётся, что нарушением не является (см. раздел 6), — это снижает ложные срабатывания.
- **Устойчивость.** Если модель не загрузилась или упала, сервис не падает: возвращает корректный ответ, а ошибку пишет в лог. Есть запасной движок через Ollama.

### Модели и лицензии
| Компонент | Лицензия | Где работает |
|---|---|---|
| Qwen/Qwen3-VL-2B-Instruct | Apache 2.0 (коммерческое использование разрешено) | локально, transformers |
| OpenCV | Apache 2.0 | локально |
| FastAPI, Uvicorn | MIT / BSD | локально |
| Ollama + qwen3-vl:2b (запасной) | MIT / Apache 2.0 | локально |

Облачные AI-сервисы не используются. Звук не анализируется. Лица не распознаются и не идентифицируются.

## 4. Нормативная база и сопоставление с видео

Использованы только акты Республики Казахстан:

| Документ | Ссылка |
|---|---|
| Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей (пост. Правления НБРК от 29.11.2019 № 231) | https://adilet.zan.kz/rus/docs/V1900019680 |
| Правила организации охраны и устройства помещений банков второго уровня (пост. Правления НБРК от 24.02.2020 № 14) | https://adilet.zan.kz/rus/docs/V2000020075 |
| Требования к обеспечению информационной безопасности банков (пост. Правления АРРФР от 03.04.2026 № 53) | https://adilet.zan.kz/rus/docs/V2600038336 |

**Принцип сопоставления.** Каждый тип нарушения в справочнике связан с наблюдаемым на видео действием и с пунктом документа. Типы и границы «нарушение / не нарушение» выведены из парного разбора всех 42 размеченных роликов: в датасете почти каждое нарушение имеет пару — ту же сцену без нарушения, — что позволило точно определить, какое именно действие считается нарушением. Пункты сверены с текстами документов. Там, где прямого пункта нет, указан документ без пункта (это допускается ТЗ). В интерфейсе есть справочник с выдержками из пунктов, примерами и ссылками на adilet.

## 5. Типы нарушений

| Тип | Что видно на видео | Норматив |
|---|---|---|
| Ценности оставлены без присмотра | кассир уходит, на столе остаются деньги, опломбированный пакет, документы или штампы | № 231, п. 20; п. 80 |
| Деньги предыдущего клиента не убраны | новый клиент обслуживается, деньги прошлого лежат на столе или кладутся в одну стопку | № 231, п. 20 |
| Дверь кассы открыта | кассир внутри, дверь кассового помещения не закрыта | № 14, п. 8 |
| Рабочее приложение оставлено открытым | кассир уходит, на компьютере открыто рабочее приложение | АРРФР № 53 |
| Сейф оставлен открытым | дверца сейфа открыта во время работы с деньгами | № 231, п. 20 |
| Ключ оставлен в замке сейфа | сейф закрыт, ключ в замке, кассир уходит | № 231, п. 20, п. 76 |
| Пересчёт денег без клиента | клиент уходит до окончания пересчёта своих денег | № 231, п. 20 |
| Параллельное обслуживание | кассир принимает документы второго посетителя, пока операция с первым не завершена | № 231 (документ) |
| Пакет принят без сопроводительных документов | опломбированный пакет передан без документов | № 231, п. 24 |
| Не проведена проверка подлинности | после счётной машины купюры сразу в стопку, без УФ и ручного пересчёта | № 231, пп. 57–58 |
| Деньги из вскрытой упаковки без пересчёта | упаковка вскрыта, деньги убраны в сейф мимо счётной машины | № 231, п. 25 |
| Личные вещи на рабочем месте | сумка, куртка на столе кассира | № 231, п. 12 |
| Еда и напитки рядом с наличными | кассир ест или пьёт, деньги не убраны | № 231, п. 20 |
| Использование телефона при работе с наличными | кассир пользуется телефоном, пока на столе деньги или идёт пересчёт | № 231, п. 12 |
| Выдача купюр из пачки клиента | после пересчёта кассир вынимает купюры из принятой пачки и отдаёт их | № 231, п. 20, п. 31 |

## 6. Ограничения и известные случаи ошибок

**Не считается нарушением** (по разметке организаторов): клиент без документа; телефон в руке или кармане без использования; дверь закрыта, но не заперта; горящий экран без открытого приложения; свет включён; кассир работает одна; деньги на столе, пока кассир с ними работает; проверенные купюры в одной стопке.

**Ограничения:**
- **Мелкие объекты.** Ключ в замке сейфа, номиналы купюр, отбракованная купюра плохо различимы на общем плане — эти типы распознаются хуже.
- **Отсутствие действия.** Нарушения вида «не сделал проверку» (без УФ-лампы, без пересчёта) модель находит хуже, чем видимые объекты.
- **Таймкод** указывает на окно, где нарушение замечено (окна по 3 с); точность — в пределах окна.
- **Длинные ролики.** Если все окна не помещаются в бюджет времени, модель смотрит самые активные окна и равномерную выборку; короткие нарушения в спокойных отрезках могут быть пропущены.
- **Новые ракурсы и типы.** Подход не привязан к расположению объектов, но качество на другом ракурсе может отличаться от обучающего.
- **Невидимые данные.** Сервис не утверждает нарушения, для которых нужны данные вне видео (проводки, сверки, оформление в АБИС).
- **Скорость** зависит от видеокарты; на CPU анализ медленнее и смотрит меньше окон.
- **Один спорный ролик разметки** (X-2): тип нарушения по видео однозначно определить не удалось.
